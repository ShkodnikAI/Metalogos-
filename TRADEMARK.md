# The Metalogos Trademark Policy — the neutral use of the name and the logo

The policy of the «Metalogos» name and the logo — the institutional
contour, ADR-0219 (the roster items 1–4; the 8H-1 / C13б subphase).
The code is licensed MIT / Apache-2.0 — the license grants the right
to use, copy, modify and redistribute THE CODE; it does not grant the
right to present a modified build, a fork, or an unrelated product as
«Metalogos». This page draws that line.

## 1. Scope — the name and the logo

This policy covers:

- the name «Metalogos» in any spelling and casing (Metalogos,
  METALOGOS, metalogos), including compound marks where «Metalogos» is
  the distinctive element («Metalogos Pro», «Metalogos Cloud» and the
  like);
- the project logo — the badge/wordmark assets the repository README
  and the release pages render;
- the combination of the name with a product, a service, or a domain
  in a way likely to cause confusion about origin.

Not covered: the `.mlog` file extension, the language grammar and the
standard library (they are code, licensed per LICENSE), and the
unmodified factual references to the project (§2).

## 2. Permitted use

No prior permission is needed for:

- honest reference: stating that a project, an article, a talk, or a
  course is about, based on, or compatible with Metalogos, with a link
  to the repository;
- truthful compatibility statements («works with Metalogos v0.38» —
  accurate for the stated version);
- non-commercial mention in research, education, journalism, and
  community discussions;
- redistribution of an UNMODIFIED release build under its license
  terms;
- nominative use: referring to the project by its name when no other
  word serves.

## 3. Forbidden use and the anti-endorsement rule

Not permitted without a written permission (§4):

- presenting a modified build, a fork, or a repackage AS «Metalogos»:
  a modified build must be explicitly marked as modified and
  unaffiliated (for example, «X — a fork of Metalogos v0.38, not
  affiliated with the original project»);
- names, domains, or marks that imply endorsement, sponsorship, or
  affiliation that does not exist;
- logos or wordmarks confusingly similar to the project's;
- using the name in a way that implies the project endorses a
  product, a service, or a political position;
- registering a trademark, a domain, or a company name containing
  «Metalogos» without the permission recorded in §4.

**The anti-endorsement rule:** the absence of a written permission
statement means NO endorsement. Neither the GitHub organization, nor
the repository, nor a release, nor a star implies any approval of a
third-party product. A fork is not Metalogos — the fork's own name and
its own marks are its own responsibility.

The license of the code (MIT / Apache-2.0) and this policy are
independent: the right to the code does not carry the right to the
name or the logo.

## 4. The permission-request channel

To request a permission, open a GitHub issue on the repository
(https://github.com/ShkodnikAI/Metalogos-/issues) with the title
prefixed `trademark request:` — describe the use, the surface (a
product, a domain, an event, a publication), and the duration. The
decision follows the governance document ([docs/GOVERNANCE.md](docs/GOVERNANCE.md)):
the BDFL decides and the decision is recorded in the issue. No other
channel exists for trademark requests; do not use the security
contact for them (the vulnerability channel is [SECURITY.md](SECURITY.md)).

A granted permission is a written statement in the request issue —
nothing else counts as a permission.

# ADR-0139: SMFS — экспорт памяти как виртуальной read-only ФС (`sm:`)

**Status:** Proposed (черновик спайка №282; вердикт спайка — GO)
**Date:** 2026-09-13
**Naryad:** #282 (спайк, issue #331; прототип — draft PR #349, ветка `naryad-282-smfs-profile`, в main не мержится)
**Related:** ADR-0041 (memory persistence), ADR-0093/0094 (memory typology / type-aware recall), №281 (user_profile), ADR-0131 (diagnostic codes), ADR-0136 (redact), №284 (canary), №252/№254 (sandbox), ADR-0096 (concurrency)

## Context

supermemory SMFS подтверждает нишу «память как файловая система»: контейнер памяти монтируется как директория, в корне — виртуальный read-only `profile.md` («cat profile.md» вместо обхода файлов), заявленные ~3× экономии токенов против обхода. В Metalogos профиль контейнера уже существует — детерминированный `user_profile` (№281), но он доступен только прямым вызовом builtin, и его Struct-форма не встраивается в файлово-ориентированные сценарии (шаблоны, LLM-контекст «как из файлов», скрипты навигации).

Спайк №282 (отчёт `docs/research/naryad-282-smfs-spike.md`) проверил на прототипе: может ли память языка отдаваться через **существующие** файловые builtins без расширения песочницы №131/№252/№254 — и даёт ли это измеримое сокращение контекста.

## Decision (проект для продуктовой реализации)

1. **Виртуальное пространство `sm:`** — read-only экспорт kv-памяти поверх `user_profile` (№281):

   | Путь | Операция | Результат |
   |---|---|---|
   | `sm:` | `list_dir` | смонтированные БД (в продукте — реестр mount-точек, не скан корня) |
   | `sm:<db>` | `list_dir` | контейнеры |
   | `sm:<db>/<container>` | `list_dir` | `profile.md` + бакеты |
   | `sm:<db>/<container>/profile.md` | `read_file` | детерминированный дайджест (обрезка + указатели на полные записи) |
   | `sm:<db>/<container>/<bucket>/<key>` | `read_file` | полное значение записи |

2. **Read-only монтирование**: `write_file`/`append_file`/`delete_file` в `sm:*` — громкая ошибка `[SMFS_READ_ONLY]` (ADR-0131-код). Запись в память остаётся за `memorize`/`kv_set` (один writer; sugar-запись — отдельное решение, не входит).

3. **Резервация префикса в обе стороны**: пути `sm:*` обрабатываются только виртуально (перехват до `sandbox_path`); реальные файлы `sm:*` через builtins недостижимы и несоздаваемы. `..` — громко `[SANDBOX_VIOLATION]`; невалидные формы — громко `[SMFS_BAD_PATH]`/`SMFS_IS_DIR`/`SMFS_IS_FILE`.

4. **Песочница не расширяется**: виртуальные пути не касаются диска (кроме штатного песочничного открытия БД профиля); активная песочница `forbidden=["filesystem"]` сильнее перехвата — виртуальный доступ считается filesystem-доступом.

5. **Детерминизм**: дайджест рендерится без LLM (переиспользует кэш №281); LLM-сводка — отдельный продукт-контур (стриминг №275, bounded-per-chunk), не часть этого решения.

## Consequences

- **Позитив**: замер спайка — сокращение контекста **3.66×** против обхода всех записей (Go-критерий ≥ 2×); «memory-native filesystem»-нарратив для гранта; доступ к памяти из любого файлового сценария без новых builtins; реестр/арности/bytecode-индексы не меняются.
- **Позитив**: canary-детекция (№284) сквозь экспорт сохраняется (прототипный тест); экспорт не создаёт нового taint-канала относительно `user_profile`.
- **Негатив/границы**: резервация префикса делает реальные файлы `sm:*` недостижимыми через builtins (обратная совместимость — осознанная плата, объявляется громко); дайджест-параметр (160 симв) требует настройки; выигрыша нет на памяти из коротких записей; токен-прокси chars/4 без токенизатора.
- **Фоллоу-апы**: реестр mount-точек (замена скана корня); tainted-пометки записей, созданных из tainted-выражений; фоллоу-ап хотфикс sandbox-гейта `eval_expr`-пути (находка спайка §5 отчёта — pre-existing пробел, починен на спайк-ветке).
- **Точка пересмотра**: появление продуктовой записи через memory-paths (SMFS-семантика «запись генерирует воспоминание») — требует отдельного ADR с гейтами кэша/ledger/taint.

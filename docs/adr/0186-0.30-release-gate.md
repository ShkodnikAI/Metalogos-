goal already achieved by the live fact measures nothing. Every parameter
in §3 sits STRICTLY ABOVE the live fact at the draft's start (main @

the 0.29 draft honored (3500 > 3241; the X-3 corrective 3000 precise >

   never lifts a gate and never publishes.

## §5. The parameter-change rule (the ADR-0181 §5 shape)

The parameters are fixed by the OWNER, changed by the OWNER, and never
by the executor. The draft → fixed transition is ONE mechanical edit in
ONE PR: `owner_fixed: false → true` in `gate_030_goals.txt` + this ADR's
Status line Proposed → Accepted + the DEFAULT gate target switch in
`unfreeze_gate.py` ('0.29' → '0.30') — the switch happens ONLY in the
merge where `owner_fixed` flips true (the №597 pattern: the parameters
first, the CI ratchet after). A later value change follows the same
owner-only path with the change recorded in the goals-file header.

## §6. Honest limits

- The draft's parameters are the executor's arithmetic above the live
  facts, not a negotiated contour — the owner may fix any values,
  including ones that demand MORE movement (the honest-direction bias).
- The gate read for the draft is available but NOT wired: no CI job
  reads `--gate-target 0.30` until the fixation merge; the blocking CI
  keeps reading 0.29.
- The typed/precise metrics count the stage-0 vocabulary (the bare
  scalars precise; List/Struct typed-but-coarse, №560) — the parameterized
  signature types (List<Param>, Struct(Name)) remain the stage-1+ work
  (the ADR-0178 line, the owner's stage-2 gate).
- No new fact_* keys: the 0.30 record verifies through the SAME checkers
  as 0.28/0.29; a future parameter needs its checker FIRST (№525).

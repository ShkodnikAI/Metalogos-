## Кто создаёт ветви и зачем

- **Исполнитель** — по ветви на наряд (`naryad-NNNN-*`): main защищён (enforce-admins, no bypass), всё идёт через PR + зелёный CI — merge rule (а), машина владельца.
- **dependabot** — `dependabot/cargo/*`.
- **weekly watchlist-workflow** (№993) — rolling `watchlist-digest` (Actions в этом репо не может создавать PR — дайджест-артефакты паркуются на ветви).
- **release-train** — `release/*` на время поезда.

`delete_branch_on_merge` = **true** (проверено 24.11): мерж-ветви не копятся. **Дырка**: закрытие PR **без мержа** ветвь не удаляет — осиротевшие головы висели именно поэтому. PR-"probe" #2056 (23.11) — инцидент того же класса, погашен тем же днём.

## Правило гигиены ветвей

- **(а)** Закрыл PR без мержа — удали головную ветвь тем же актом (автоудаление покрывает только мерж).
- **(б)** Долговечные ветви только: `main`, `watchlist-digest`, головы открытых PR, активные release-ветви поезда.
- **(в)** Ежемесячный sweep — сверка списка ветвей с этой таблицей.
- **(г)** Никаких PR-"probe" (урок #2056: настоящий PR из payload).

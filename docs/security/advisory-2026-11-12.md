# Security Advisory — 2026-11-12: the label lattice is intraprocedural; `check --root` and `mlog test` execute without gates

**Status:** published (the text of record — the GitHub Security Advisory publication is the owner's act)
**Affected versions:** all releases ≤ 0.39.0 (the language core as of main `750e8119`)
**Fixed in:** `0.39.1` (№953 — `check --root` / `mlog test`; №954 — capability permits; №955 — error texts / serve 500) and the next minor `0.40.0` (№950–№952 — the inter-pattern label lattice, ADR-0154/ADR-0156 as amended by №949)
**Discovered by:** the total audit 12.11.2026 (main `750e811`, release v0.39.0, sha256-verified binary; every finding reproduced on the published release)
**Full boundary table:** [docs/threat-model.md §The inter-pattern boundary](../threat-model.md#the-inter-pattern-boundary-948--the-audit-1211-table)

## Summary

The README of ≤ 0.39.0 promised: «secret leaks, injection and unauthorized irreversible actions are rejected before the program runs». The promise holds **only within a single pattern**. The taint/label analysis is intraprocedural: a value produced by a source (`env()`, `query_param()`, `call_llm()`, request input) that crosses a call into a user-defined pattern is not tracked — `mlog check` passes and the program leaks at run. Three more gaps sit outside the lattice: `mlog check --root` and `mlog test` execute the programs they should only analyze, without the Category-A gates; an imported module can extend the capability permit roster by declaring its own `profile capability`; runtime error texts quote argument values and `serve` returns them to the client.

## Impact

1. **Secret exfiltration through a helper pattern** — `pattern Key(x) { return env("KEY") }` + `http_post(url, Key("a"))`: check passes, the secret leaves to the network (also: a parameter reaching a sink inside the pattern; a two-pattern chain; the HTML lane — a working XSS under `serve`; the exec lane — model output steering a shell command).
2. **Label loss inside one pattern** — the `each` accumulator, a secret interpolated into an `http_get` URL, a flow step returning a source value, a `Secret` entity read back via `to_string`.
3. **Arbitrary code execution under the analysis commands** — `mlog check <file> --root <root>` runs the root program (its `write_file`/`print`/route bodies execute BEFORE the analysis, without the Category-A gates `mlog run` applies); `mlog test` runs test bodies without the gates. Both are recommended in project documentation and stand in consumer CI pipelines.
4. **Dependency self-grant** — an imported module declaring `profile capability { allow_carrier: "http_post" }` extends the permit roster: any dependency grants itself network/exec.
5. **Secrets in error surfaces** — a runtime type error quotes the argument value (`to_int("TOPSECRET…")`); under `serve` the full text is returned to the client in the HTTP 500 body.

## Workarounds (until the fixes land)

- Annotate pattern parameters explicitly (`String<private>`) — an annotated parameter is checked at the call site today; the unannotated-parameter gap is closed by №950.
- Put `redact()` between the source and the sink; never pass a source value across a pattern call unredacted.
- Do NOT run `mlog check --root` or `mlog test` on code you do not fully trust; treat both as EXECUTION, not analysis.
- Keep `profile capability` declarations in the entry program only; treat every dependency as holding the permits it declares.
- Do not surface runtime error texts to untrusted clients (strip 500 bodies at the proxy until №955).

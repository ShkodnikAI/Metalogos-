# Naryad №959 (issue #1926, the audit 12.11 — P1): the CLASS of every
# Phase-8 machine fact, and the USER SURFACE of every capability slot.
#
# The fact this roster answers (the issue's §Факт): the Phase-8 machine
# facts count the PRESENCE OF AN ANCHOR — a decision name in a test file,
# `pub fn replay_gate` in a module, eight test-function names, twelve
# headings, a seed region. An anchor is a real thing to check and the
# gates that read them are honest gates, but an anchor is not a BEHAVIOUR:
# a tree can carry every anchor of a capability no user can invoke. Read
# as readiness, `TERMINAL_STOP 13/13` says more than the tree can support.
#
# So each fact now declares its class, and each slot its surface, and both
# are CHECKED against the live tree rather than declared:
#
#   class=structural   the fact counts an anchor in the tree. The anchor
#                      must exist (`evidence`), or the row fails.
#   class=behavioural  the fact's number is produced by an EXECUTED test
#                      that counts real outcomes and asserts them against
#                      the fact itself. Such a row MUST also carry
#                      `exec=<file>#<needle>`, and both the file and the
#                      needle must be live — otherwise the row fails. That
#                      is the mutation the issue names: declaring a
#                      structural fact behavioural without an executable
#                      test turns `gen_metrics --check` RED.
#
#   surface=builtin | cli | declaration
#                      the slot's capability can be invoked by a user
#                      through a builtin, a CLI subcommand or a language
#                      declaration. `evidence` names the file that proves
#                      it.
#   surface=analyzer   the module runs on the `mlog check`/run path, so a
#                      user action exercises it, but nothing in the
#                      language or the CLI addresses it directly.
#   surface=kernel-only
#                      reachable only from library code and tests. The
#                      capability exists; a user cannot reach it.
#
# The surface verdicts were MEASURED, not assumed: for each slot's module
# the scan looked for `<leaf>::` references and sorted the referring files
# into builtins / CLI / analyzer / library / tests. A first attempt
# searched `crate::<leaf>::` only and reported "no references" for every
# nested module (`nn/attest`) — that was the scanner's defect, not a
# finding, and it is why the evidence path rides every row: a verdict with
# no file behind it is not a verdict.
#
# Format (one row per fact, `#` starts a comment):
#   slot <Cn> fact=<NAME> class=<class> surface=<surface> module=<path>
#        evidence=<path>#<needle> [exec=<path>#<needle>]
#
# The needle is matched as a literal substring of the named file, and
# `module` is the slot's implementation module. The gate checks BOTH
# directions: the evidence needle must be live, AND the declared surface
# must agree with a live reachability scan of `module` — a `kernel-only`
# row fails the moment a builtin or the CLI starts referencing it (which
# is the right failure: the row must then be updated, in the same PR as
# the wiring), and a `builtin`/`cli`/`declaration` row fails if that
# reference disappears.

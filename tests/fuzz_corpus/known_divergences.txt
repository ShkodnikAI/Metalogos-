# The KNOWN TW/VM divergence classes — the ratchet (№465 fuzzer, №476 rule, №479 readability).
#
# Policy (the spirit unchanged since №465, the form readable since №479):
#   * a class signature = the STABLE error codes (ADR-0131) of the two
#     sides + the AST node kind each error was born at (`@fn_call`,
#     `@ident`, `@binary_op`, `@each`, `@other`); `err:uncoded(...)` on a
#     side means the origin site lacks its stable code — assign the code
#     first, then pin;
#   * every signature line is preceded by a comment block carrying
#     `# class:` (the human description), `# example:` (a checked-in
#     minimal program that REPRODUCES the class every run) and
#     `# status:` (open / closed by <naryad>). The corpus parse FAILS CI
#     when a line loses its block — the audit 26.09 §3.4 defect (an
#     unreadable corpus absorbs new divergences of the same shape)
#     cannot regress;
#   * the example is LOAD-BEARING: when it stops reproducing the class,
#     the gap is CLOSED — the run fails demanding the line and the
#     example be removed in the fix PR (the corpus never outlives the
#     divergence it pins);
#   * NEW classes enter ONLY with the naryad report that explains them
#     (the known verdict per rule №476); the minimized catch of the run
#     that found them is in `target/fuzz_min/`.
#
# ── №476 (gh#724): the BLOCKED-DOMAIN rule ──────────────────────────────
# Classes touching SQL, filesystem, network, exec, labels, or secrets are
# BLOCKING correctness errors — pinning them as known is FORBIDDEN:
#   * a `blocked-`-prefixed line in THIS file fails CI with the line
#     named (there is nothing to pin in a blocked domain — fix it);
#   * at run time, a divergence whose raw text carries a blocked-domain
#     marker (database/sql/sqlite, read/write_file/fs_gate, http/socket,
#     exec/shell, label/taint, secret/credential) NEVER matches as known
#     — the run fails naming the class, even if someone pinned it here;
#   * the №479 stateful generation (db / llm mock / mail refusal) makes
#     those domains FUZZED: a backend divergence there is caught by the
#     fuzzer itself and repaired by a naryad, never pinned.
#
# History: the pre-№479 corpus carried 8 normalized-prose lines (the
# №474 cleanup had removed the 3 SQL-adjacent shapes). The №479
# migration re-derived every class from RAW behavior — the 8 unreadable
# `iiii: iiiiiiiii iiiiiiii` lines collapse into the 5 coded classes
# below (the same root causes, readable signatures, checked-in
# examples). Stable codes assigned at the origin sites by №479:
# UNDEFINED_VARIABLE / UNDEFINED_FUNCTION / TYPE_MISMATCH (ADR-0131
# convention, both backends, parity-pinned).
#
# ── №503 (gh#786): the OUTCOME rule ─────────────────────────────────────
# A divergence where one side is ok and the other is err is a correctness
# defect BY SHAPE — the same program must not succeed on one backend and
# fail on the other. Outcome classes are un-pinnable (a known-outcome line
# fails the parse like a blocked- line) and never match as known at run
# time. Wave 19: both former outcome classes left the corpus — the
# entity-in-pattern gap is FIXED (the TW ident read falls back to the
# declaration globals, parity with the VM); the memory_forget compile gap
# is root-caused in gh#786 with the repair plan (the vec-gate/soft-fn
# semantics decision belongs to the owner).

# class: phase family — TW reports a runtime type mismatch in concatenation
#   ([TYPE_MISMATCH]@binary_op) while the VM refuses EARLIER at compile
#   (memory_forget, [UNDEFINED_FUNCTION]): both error, the construct and
#   the phase differ.
# example: class_example_phase_concat_vs_compile.mlog
# status: open — phase-parity family; repaired by the transfer/parity line, never pinned silently
known-errorclass|tw=err:[TYPE_MISMATCH]@binary_op|vm=err:[UNDEFINED_FUNCTION]@fn_call

# class: phase family — TW reports a builtin argument type mismatch
#   (len() over a non-String/List, [TYPE_MISMATCH]@fn_call) while the VM
#   refuses EARLIER at compile (memory_forget, [UNDEFINED_FUNCTION]).
# example: class_example_phase_lenarg_vs_compile.mlog
# status: open — phase-parity family; repaired by the transfer/parity line, never pinned silently
known-errorclass|tw=err:[TYPE_MISMATCH]@fn_call|vm=err:[UNDEFINED_FUNCTION]@fn_call

# class: phase family — TW reports an undefined variable at runtime
#   ([UNDEFINED_VARIABLE]@ident) while the VM refuses EARLIER at compile
#   (memory_forget first, [UNDEFINED_FUNCTION]).
# example: class_example_phase_ident_vs_compile.mlog
# status: open — phase-parity family; repaired by the transfer/parity line, never pinned silently
known-errorclass|tw=err:[UNDEFINED_VARIABLE]@ident|vm=err:[UNDEFINED_FUNCTION]@fn_call
